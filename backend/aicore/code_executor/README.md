# Code Execution System for LLM Agents

This module provides a secure and isolated environment for running Python code and system commands generated by Large Language Model (LLM) agents.

## Overview

The system enables agents to perform tasks requiring code execution, such as data analysis, calculations, file operations, and environment setup, within a controlled sandbox.

## Key Features

- **Isolated Execution**: Each code snippet runs in a fresh, temporary namespace, preventing interference between executions.
- **Input/Output Capture**: Captures standard output (stdout), standard error (stderr), and the final result variable.
- **Process-Based Isolation**: Executes code in separate processes for enhanced safety and proper timeout handling.
- **Timeout Management**: Enforces configurable execution time limits to prevent infinite loops or resource exhaustion.
- **Asynchronous Operation**: Utilizes `asyncio` for non-blocking execution, allowing concurrent operations.
- **Unique Execution Context**: Uses message IDs for tracking and namespacing outputs (like plots).
- **Resource Management**: Includes cleanup mechanisms for resources (e.g., matplotlib figures, temporary files) after execution.
- **Controlled System Commands**: Allows execution of specific system commands (e.g., `pip install`) for environment setup, with security checks.
- **Agent Integration**: Provides a specialized `CodeExecutorAgent` class that handles message IDs and plot directories.
- **Web Search Tool**: Includes integration with web search capabilities for up-to-date information.
- **Comprehensive Logging**: Detailed logging throughout the execution process.

## Components

- **`code_executor.py`**: Contains the core logic for running Python code in isolated processes with timeout handling. Includes functions like `execute_in_process`, `execute_async`, and `execute_code_string`.
- **`code_tool.py`**: Defines the Pydantic models (`CodeExecutionResult`, `SystemCommandResult`) and the `@function_tool` decorated functions (`execute_code`, `execute_system_command`) that agents interact with.
- **`code_agent.py`**: Implements the `CodeExecutorAgent` class that manages message IDs and plot directories, and includes WebSearchTool integration.
- **`utils.py`**: Provides utility functions, including the `execution_cleanup` context manager for resource cleanup (matplotlib figures, temporary files).
- **`logger.py`**: Configures logging for the code executor module with customizable log levels.
- **`test_code_tool.py`**: A comprehensive test suite demonstrating how to set up an agent with the tools and run various prompts.

## Core Concepts

### Process-Based Isolation

The system executes code in separate processes for enhanced isolation and safety:

```python
# code_executor.py
def execute_in_process(code_string: str, timeout: int) -> Dict[str, Any]:
    """Execute code in a separate process with proper timeout handling."""
    # Create a queue for results
    result_queue = mp.Queue()
    
    # Create and start process
    process = mp.Process(
        target=process_executor,
        args=(code_string, result_queue),
        daemon=True
    )
    
    # Start process and handle timeout
    process.start()
    process.join(timeout)
    
    if process.is_alive():
        # Process is still running after timeout - terminate it
        process.terminate()
        # Return timeout error
        return {
            "result": None,
            "stdout": "",
            "stderr": f"Code execution timed out after {timeout} seconds and was terminated.",
            "status": "error",
            "error": f"Execution timed out after {timeout} seconds"
        }
    
    # Process completed, get results from queue
    if not result_queue.empty():
        return result_queue.get()
    else:
        # Process exited but didn't put anything in queue
        return {
            "result": None,
            "stdout": "",
            "stderr": "Process terminated without returning results",
            "status": "error",
            "error": "No results returned from execution process"
        }
```

### Timeout Management

The system enforces configurable execution time limits to prevent runaway code:

```python
# Default timeout for code execution
DEFAULT_TIMEOUT = 30  # seconds

async def execute_code_string(code: str, timeout: int = DEFAULT_TIMEOUT) -> CodeExecutionResult:
    """
    Execute a code string with timeout and return a structured result.
    """
    try:
        # Execute code in process with timeout
        result_data = await execute_async(code, timeout)
        
        # Return structured result
        return CodeExecutionResult(
            result=result_data.get('result'),
            stdout=result_data.get('stdout', ''),
            stderr=result_data.get('stderr', ''),
            status=result_data.get('status', 'success'),
            error=result_data.get('error')
        )
    except Exception as e:
        # Handle any unexpected exceptions
        return CodeExecutionResult(
            result=None,
            stdout="",
            stderr=str(e),
            status="error",
            error=str(e)
        )
```

### Asynchronous Execution

The use of `asyncio` and process-based execution allows the system to handle potentially long-running code executions without blocking the main application thread:

```python
# code_executor.py
async def execute_async(code_string: str, timeout: int) -> Dict[str, Any]:
    """
    Execute LLM-generated code string in an async context with proper timeout.
    """
    loop = asyncio.get_event_loop()
    
    # Use process-based execution with proper timeout handling
    return await loop.run_in_executor(None, lambda: execute_in_process(code_string, timeout))
```

### Resource Cleanup

The system includes cleanup mechanisms to ensure resources are properly managed after code execution:

```python
# utils.py
@contextmanager
def execution_cleanup():
    """Context manager for resource cleanup after code execution."""
    try:
        yield
    finally:
        try:
            # Close any matplotlib resources
            try:
                import matplotlib.pyplot as plt
                plt.close('all')
            except ImportError:
                pass
            
            # Clean up temporary files
            temp_dir = tempfile.gettempdir()
            current_time = time.time()
            for temp_file in glob.glob(os.path.join(temp_dir, "tmp*")):
                try:
                    # Check if file is older than 60 seconds and not in use
                    if os.path.isfile(temp_file) and os.path.getmtime(temp_file) < (current_time - 60):
                        os.unlink(temp_file)
                except (PermissionError, OSError):
                    # Skip files that are in use or can't be deleted
                    pass
                    
            # Force garbage collection
            gc.collect()
        except Exception as e:
            logger.warning(f"Error during cleanup: {e}")
```

### CodeExecutorAgent

The system provides a specialized agent class that handles message IDs, plot directories, and includes web search capabilities:

```python
# code_agent.py
class CodeExecutorAgent(Agent):
    """
    A specialized Agent subclass for executing code with managed message IDs.
    """
    
    def __init__(self, name: str, root_plots_dir: str):
        """Initialize the CodeExecutorAgent."""
        unique_id = str(uuid.uuid4())[:8]
        self.unique_plots_dir = os.path.join(root_plots_dir, unique_id)
        os.makedirs(self.unique_plots_dir, exist_ok=True)
        
        # Current message ID for the agent
        self.current_message_id = str(uuid.uuid4())[:8]
        
        # Create web search tool
        websearch_tool = WebSearchTool(user_location={"type": "approximate", "city": "New Delhi"})
        
        # Initialize with tools
        super().__init__(
            name=name,
            instructions=self._get_dynamic_instructions,
            tools=[execute_code, execute_system_command, websearch_tool]
        )
```

## Agent Integration & Usage

Agents interact with the system via the `execute_code` and `execute_system_command` tools.

**Critical Instructions for Agents:**

1. **Self-Contained Code**: Code provided to `execute_code` **must** be a single, complete Python script, including all necessary imports.
2. **Result Variable**: To return a value, the script **must** assign it to a variable named `result`.
3. **No Memory**: Each execution is stateless. Variables or imports from previous calls are not retained.
4. **Process Isolation**: Each execution runs in a separate process with a configurable timeout (default: 30 seconds).
5. **Data Visualization**: Plots must be saved to files (not shown using `plt.show()`). The unique `message_id` should be included in the filename. The file path(s) should be included in the `result` variable.
6. **Environment Setup**: If external packages or data are needed, use `execute_system_command` *before* `execute_code`.

### Example: Basic Code Execution

```python
# Agent calls this tool
result = await execute_code("""
import math

def calculate_area(radius):
    # Performs calculation
    return math.pi * (radius ** 2)

# Assigns the final output to the 'result' variable
result = calculate_area(5)
print(f"Calculation complete for radius 5.") # Example stdout
""")

# Accessing results
print(f"Result: {result.result}")       # Output: 78.53981633974483
print(f"Stdout: {result.stdout}")     # Output: Calculation complete for radius 5.
print(f"Status: {result.status}")     # Output: success
```

## Security Considerations

- **Process Isolation**: Code runs in separate processes, limiting potential impact on the main application.
- **Timeout Enforcement**: All code executions have a configurable timeout (default: 30 seconds) to prevent resource exhaustion.
- **Restricted System Commands**: `execute_system_command` defaults to allowing only `python`, `pip`, and `python -m` commands to mitigate risks associated with arbitrary command execution.
- **Namespace Isolation**: Limits the scope of executed code, preventing unintentional modification of the main application's state.
- **Resource Cleanup**: Automatically closes resources like matplotlib figures and cleans up temporary files.
